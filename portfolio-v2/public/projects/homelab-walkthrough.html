1. System Overview

REF: STE-OVERVIEW-01

This home lab runs container orchestration, security checks, workflow automation, DNS filtering, and central monitoring across four Raspberry Pi boards.

Each board operates on local network 192.168.2.0/24. Physical board separation keeps heavy disk writes from slowing down other services.

Each node uses a dedicated operator account without root privileges (k8sops, gops, and n8nops).

Central Prometheus collects telemetry from five endpoints every 30 seconds. Grafana shows system health on port 3000.

3. Operating and Maintenance Procedures

REF: STE-PROC-03

3.1 Prepare Control Plane and Security Rules (microk8sMaster)

  1. Install Ubuntu 24.04 LTS on a V30 A2 microSD card.
  2. Install MicroK8s v1.35.6 and enable dns, hostpath-storage, metrics-server, and rbac.
  3. Create three namespaces: cka-lab, devsecops, and monitoring.
  4. Install Kyverno and apply policy disallow-latest-tag to block unpinned :latest container images.
  5. Install Trivy to scan container images for high and critical vulnerabilities.
  6. Expose kube-state-metrics on NodePort 30808 and verify node_exporter on port 9100.

3.2 Configure Edge DNS Exporters (pizero-pihole)

  1. Download the linux-armv6 release of node_exporter and install it as a systemd service on port 9100.
  2. Download the linux_armv6 binary of pihole-exporter.
  3. Set executable permissions on /usr/local/bin/pihole_exporter with chmod +x.
  4. Start pihole-exporter and verify DNS metrics at http://192.168.2.148:9617/metrics.

3.3 Start Observability Hub (ubuntu-Host)

  1. Create host directory /opt/grafana-data and set owner UID:GID to 472:472.
  2. Set GF_DATABASE_WAL=true and GF_DATABASE_BUSY_TIMEOUT=10000 in docker-compose.yml.
  3. Set Prometheus scrape interval to 30s and cap storage retention at 7d or 1GB.
  4. Run docker compose up -d as operator gops in /home/gops/observability.
  5. Connect Grafana to Prometheus through internal bridge DNS URL http://prometheus:9090.

3.4 Verify Target Health

  1. Open http://192.168.2.176:9090/targets in a web browser.
  2. Confirm all five scrape targets show state UP.
  3. Open Grafana at http://192.168.2.176:3000.
  4. Inspect CPU load, RAM use, microSD disk busy time, pod counts, and Pi-hole block rates.

4. Fault Isolation and Corrective Actions

REF: STE-FAULT-04
Fault Condition Probable Cause Corrective Action
MicroK8s API server freezes under load on microk8sMaster Slow random 4K write speed on standard microSD card delays kine database commits. Install Ubuntu 24.04 LTS and MicroK8s on a V30 A2-rated microSD card.
Grafana web page locks with SQLITE_BUSY error Concurrent alert and dashboard writes lock grafana.db on microSD storage. Enable SQLite WAL mode (GF_DATABASE_WAL=true) and set GF_DATABASE_BUSY_TIMEOUT=10000.
Grafana fails to connect at legacy port 30678 Docker Compose binds Grafana to host port 3000 instead of legacy Kubernetes NodePort 30678. Connect to http://192.168.2.176:3000 and route internal queries to http://prometheus:9090.
pihole-exporter fails to start on pizero-pihole ARM64 or ARMv7 binary cannot run on the Raspberry Pi Zero W ARMv6 processor. Replace binary with the linux_armv6 build and run chmod +x.
sudo ufw status fails for operator gops Operator gops has no root privileges by design. Run host firewall checks with administrator account ubuntu. Keep container tasks under gops.
