SECTION 1 System Architecture & Components

Architecture & Subsystem Overview

1.1 Frontend Application

React + Vite
  • React and Vite build a fast single-page application inside the portfolio-v2 directory.
  • Tailwind CSS styles responsive layouts for desktop, tablet, and mobile screens.
  • The Projects.jsx component filters engineering work by cloud, automation, and Kubernetes tags.

1.2 Edge Routing & Static Demos

Edge CDN
  • The staticwebapp.config.json file controls URL routing and fallback rules at the edge.
  • Navigation fallback exclusions allow direct browser access to standalone *.html files.
  • The public/projects/ folder stores interactive architecture walkthroughs without React router interference.

1.3 Serverless Contact Backend

Azure Functions
  • Azure Functions hosts the managed /api/contact HTTP endpoint without dedicated virtual machines.
  • The API handler validates sender fields and blocks malformed or empty form payloads.
  • Serverless scaling allocates compute resources during recruiter visits and reduces idle cost to zero.

1.4 Email Delivery Pipeline

SendGrid / Graph
  • The contact function connects to SendGrid or Microsoft Graph APIs over encrypted HTTPS channels.
  • The mail relay delivers recruiter messages directly to the operator inbox.
  • The API returns an HTTP 200 status so the interface displays delivery confirmation.

1.5 Custom Domain & SEO

DNS + Search
  • Custom DNS records bind luzon.arcilla.org to the Azure Static Web Apps endpoint.
  • Google Search Console verifies domain ownership and monitors crawl health.
  • Structured metadata and URL inspection index portfolio pages for technical recruiter searches.

1.6 CI/CD & Staging Environments

GitHub Actions
  • GitHub Actions executes automated builds whenever you open or update a pull request.
  • Azure Static Web Apps creates an isolated staging URL for every open pull request.
  • Merging into main deploys production code and removes the temporary staging environment.

SECTION 2 Operational & Deployment Procedures

Standard Operating Procedures

Procedure A: Test Changes in Staging

Workflow
  1. Create a new feature branch from main on your local Git workstation.
  2. Commit your tested code changes to the local feature branch.
  3. Push the feature branch to the remote GitHub repository.
  4. Open a pull request against main to start the GitHub Actions build.
  5. Verify all visual layouts and links on the generated Azure staging URL.

Procedure B: Add Interactive Walkthrough

Content
  1. Remove all session tokens and external debug scripts from the HTML file.
  2. Save the sanitized HTML file inside portfolio-v2/public/projects/.
  3. Confirm that staticwebapp.config.json excludes /*.html and /projects/*.html from fallback rewrites.
  4. Add the project entry and walkthrough URL to Projects.jsx.
  5. Test the walkthrough button in staging to confirm direct HTML loading.

Procedure C: Release & Verify Production

Release
  1. Merge the approved pull request into the main branch on GitHub.
  2. Delete the remote and local feature branches after the merge completes.
  3. Open https://luzon.arcilla.org to verify the live production deployment.
  4. Submit a test message through the contact form to verify /api/contact delivery.
  5. Request URL indexing in Google Search Console for new public pages.

SECTION 3 Security & Compliance Controls

Security Baseline // Zero Client-Side Secrets

3.1 Secret Management

Zero Exposure
  • The repository never stores API keys, mail credentials, or deployment tokens in client source files.
  • Azure Static Web Apps injects encrypted application settings into the serverless runtime environment. 
Client Bundle: Zero secrets in Vite output
Azure Function: process.env.SENDGRID_API_KEY

3.2 Static HTML Sanitization

Hygiene
  • Operators strip local editor scripts, Firebase tokens, and session identifiers before public commits.
  • Self-contained inline styles and scripts prevent external third-party script injection risks. 
Audit Check: 0 external CDNs // 0 auth tokens

3.3 Transport & Routing Security

HTTPS + Fallback
  • Azure Edge redirects all unencrypted HTTP requests to HTTPS automatically.
  • Explicit fallback exclusions prevent unexpected route hijacking while protecting API endpoints. 
"exclude": ["/assets/*", "/*.html", "/projects/*.html"]

3.4 Serverless Input Validation

API Guard
  • The /api/contact function sanitizes user text and rejects oversized or invalid email fields.
  • Managed CORS policies restrict browser form submissions to authorized portfolio origins.
